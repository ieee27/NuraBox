# Nura Box - Project State

_Last updated: 2026-10-10 (session 2). Source of truth = the code; if this file and the code disagree, trust the code and fix this file._

## What it is
Smart pill box, 4 compartments. Each compartment: medicine name + one daily time. At the time the box alerts (LED + passive buzzer). Lid open then closed (LDR) = **taken**. Nothing within 30 min = **missed**. A bilingual web dashboard (Arabic RTL default / English, dark / light) manages schedules, doctor-patient links and reports. An ESP32 runs the web server, schedule engine, sensors, LEDs, buzzer and storage.

## ESP32 HTTP API (all JSON; CORS `*`; POST bodies are read raw so the site sends `text/plain` to avoid CORS preflight)
| Endpoint | Body / response |
|---|---|
| `GET /` | the site from LittleFS (`index.html` or `index.html.gz`); in portal mode AP clients are redirected to `/setup` |
| `GET /api/users` | array of users (**includes plain-text `pass`**) |
| `POST /api/users` | array, max 10 else `409`, each needs a valid `username`; body max 24 KB |
| `GET /api/reports` | array (NDJSON file rolled to the last 200) |
| `POST /api/report` | one record object, max 2 KB |
| `GET /api/status` | `{fw, synced, engine, time, date, epoch, ip, ssid, rssi, mode, uptime, owner, ownerName, ownerPinned, devId, remote:{enabled,connected,host}, settings:{volume,brightness,muted}, boxes:[{box,name,time,state,ldr,baseline,open,ldrOk,silenced,test}]}` |
| `POST /api/test` | `{action: leds\|due\|taken\|missed\|reset, box}` (test states revert after 2 min) |
| `POST /api/calibrate` | `{}` -> `{ok, baseline:[4]}` (lids must be closed) |
| `POST /api/device` | `{owner}` (username, `""` = automatic) -> `404` if unknown |
| `GET/POST /api/settings` | `{volume 0-100, brightness 0-100, muted}` (saved in NVS) |
| `GET/POST /api/remote` | `{host, user, pass, enabled}` / `{enabled, host, user, hasPass, connected, devId}` |
| `GET /api/wifi/scan`, `POST /api/wifi` | portal mode only |

## Data schemas
**users.json** = `[{username, role:"patient"|"doctor", name, pass, meds:{"1":{name,time:"HH:MM"},...,"4":{...}}, doctors:[usernames], pending:[usernames], created}]`

**reports.ndjson** (one JSON per line):
- dose: `{id, kind:"dose", ts, date:"YYYY-MM-DD", user, box, med, status:"taken"|"missed", source:"box"|"web"}`
- report: `{id, kind:"report", ts, date, user, name, feel:"good"|"ok"|"bad", problemBox, symptoms, notes}`
- reply: `{id, kind:"reply", ts, date, ref, user, doctor, doctorName, text}`

**Box states**: `empty, waiting, due, taken, missed, skipped`. On boot or a schedule edit, any box whose window already passed becomes `skipped` (never a false miss). Window end is clamped to 23:59:59. Midnight resets. The engine pauses until NTP syncs (no RTC).

## Behavior decisions (firmware)
- The box follows ONE patient account: NVS `owner`, else the first patient in `users.json`.
- LDR: ADC1 only, per-box baseline at boot and on `/api/calibrate`, 30 % / 300-count threshold with hysteresis, 150 ms debounce. `OPEN_IS_LOW` is one constant (see 01_HARDWARE.md).
- LEDs: waiting off, due red blink, lid open while due green, taken green 10 min, missed dim red. LEDC PWM, brightness is a setting.
- Buzzer: MIDI notes, 2-3 notes per alert, non-blocking state machine, DUE repeats every 20 s until taken / missed / silenced (GPIO25). Volume = duty 0-50 %.
- WiFi: AP `NuraBox-Setup` (WPA2, password constant `AP_PASS`, **change it**), scanned SSID list, saved in NVS, BOOT held 3 s forgets only WiFi, retry saved network every 5 min while the portal is open, mDNS `nurabox.local` (not reliable on Android).
- MQTT remote runs in its own FreeRTOS task on core 0; the engine is touched only from `loop()`.
